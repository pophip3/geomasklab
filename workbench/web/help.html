GEOMASKLAB / OFFLINE DOCUMENTATION

A reproducible record, from image to evidence.

This guide ships with the installed wheel and source distribution and uses no remote fonts, scripts or images. Import aligned masks for your own RGB images, or run the bundled real NAIP workflow. Optional model services can generate new masks.

01 / Installation and launch

For the fixed rc4 release, install geomasklab-1.0.0rc4-py3-none-any.whl in a new Python environment, then run geomasklab-ui. The complete introduction and workbench are bundled. Choose Enter workbench; Overview returns to the introduction. Experiments are stored under the working directory, or a directory specified with --data-dir. The following source-based path displays the same interface.

Install Python 3.10 or newer. Extract the source archive into a writable folder. From its root:

python -m venv .venv
# Windows:
.venv\Scripts\python -m pip install -r requirements-reviewer.txt
.venv\Scripts\python quickstart.py
# Linux / macOS:
.venv/bin/python -m pip install -r requirements-reviewer.txt
.venv/bin/python quickstart.py

Open http://127.0.0.1:4180. Run python quickstart.py --port 4182 to use another port. Stop with Ctrl+C. After installing dependencies, use bin\geomasklab.cmd on Windows or sh bin/geomasklab.sh on Linux/macOS. Both accept --port.

The offline workflow requires only Pillow, with no GPU, weights, accounts or services. Run python reviewer_demo.py for five examples and verified evidence bundles.

02 / Choose an image and define a task

New experiment starts with an urban procedural example. Change image accepts RGB PNG, JPEG or WebP. The image library includes an airport example. Each procedural image supports one fixture category. Unsupported categories fail instead of producing a fabricated mask.

Quick segmentation selects an explicit target and scope. Free-form requests include:

Extract only buildings in the whole image.
Extract aircraft in the right half.
Describe the scene in this image.

Draw a rectangle with Draw ROI and select Drawn rectangle. Quick whole-image/half-image tasks clear the previous ROI. Follow-up text can inherit the selected result's task context. Ambiguous requests need clarification before segmentation.

Procedural examples demonstrate software behavior. They are not satellite observations, independent ground truth or neural predictions.

03 / Inspect and measure

Expand Measurement details for scope, validity, review and integrity information; use More for advanced workflow operations. Use Export figure for the saved version's publication figure and companion config. Use Original, Overlay, Mask and the display Compare slider. Overlay opacity, zoom and fit affect presentation only. Each successful mask is a separate version.

Whole-image coverage

Foreground / all image pixels. Right-half buildings: 37,350 / 480,000 = 7.78125%.

Within-region coverage

Foreground / selected region pixels. The same mask: 37,350 / 240,000 = 15.5625%.

Region & validity measures another scope from a verified full mask. It preserves prediction pixels, creates a version with pending review and performs no inference.

Inspect lists stable IDs, areas, exclusive bounding boxes, pixel-center centroids and independent image/region/invalid-boundary contact flags. Flags use 8-neighbor contact and may overlap. Minimum-area and boundary filters create a separate review layer; the source mask remains unchanged. Clipping can split one source component into several candidates.

Coverage is not accuracy. Candidate components use eight-connectivity and are not verified object counts. Pixels do not provide hectares or a geographic coordinate system.

04 / Compare result versions

With two or more mask versions, select Compare versions, then Version A and B. Both records are verified and must have the exact same image, semantic target and complement setting.

Choose Restrict to shared valid pixels or Require identical effective domains. Blue indicates removed foreground (A only), amber added foreground (B only) and mint common foreground. Geometry, validity and full-source prediction equality are reported separately. The total foreground change equals the shared-domain change plus the difference in foreground excluded from comparison; this is an accounting identity, not a causal effect allocation. Empty common domains have unavailable pixel differences; empty unions have undefined agreement. Export a replayable comparison ZIP with both exact sources, categorical differences, JSON and an English report.

Agreement IoU/Dice compare saved masks, not independent ground truth. Version comparison performs no inference.

05 / Experiment library and result table

Edit details saves a name, notes and pin. Experiments searches names/notes and filters pinned investigations or those awaiting review. Up to 100 recent saved experiments are listed; pinned items appear first within that list.

The ledger retains failed requests and scene responses alongside valid masks. Export table CSV includes parent/version IDs, settings, both coverage denominators, timing, execution origin and review state. Missing measurements stay blank. Formula-like text cells are exported as literal text.

Renaming an investigation does not rewrite earlier exported bundles or prediction artifacts.

06 / Review and evidence

Inspect target identity, omissions, false positives and boundaries. Record review saves a label, accepted/rejected decision and rationale for the exact result. It is self-reported review, without authenticated identity.

Export evidence saves the original image, full/final masks, overlay, measurements, result metadata, execution log, report, review history and checksums. Import evidence verifies and restores one result into a new experiment without services.

Run python -m workbench.export_bundle path/to/result.zip for standalone verification. Checks replay pixel operations and measurements; regenerated hashes do not authenticate authors. A single-result bundle does not restore absent ancestors.

07 / Explicit offline mask batches

Select Offline batch, upload a versioned JSON manifest and the exact image/mask/optional validity/reference files it names. Pairings are explicit; filenames are never guessed. Browser uploads use unique portable ASCII basenames, up to 128 files and 32 MB total. The CLI supports relative subdirectories and up to 128 samples.

Each completed sample is published atomically. Missing or invalid inputs produce an isolated failure, with unavailable measurements. Successful zero coverage is included in aggregation; empty valid domains are undefined and omitted. Macro mean is the mean of defined sample coverages; micro coverage sums their foreground and valid denominators before division.

Cancel after current sample requests cooperative cancellation at a sample boundary or before publishing the current sample. Verify & resume requires unchanged inputs, settings and software version and replays completed outputs first. OS advisory locks prevent simultaneous writers and release on process death; owned staging is safely recovered. Damaged identities, foreign files and incomplete initial metadata are rejected.

Export the replayable batch ZIP, or click Open evidence beside a completed sample to inspect, derive, compare and review it in the regular workbench.

geomasklab batch manifest.json --output batch-results
geomasklab batch manifest.json --output batch-results --resume
geomasklab export-batch batch-results --output batch.zip
geomasklab verify-batch batch.zip

The separate Model/demo batch applies a shared task to two to five saved image experiments. Its optional model execution is separate from explicit external-mask batches.

08 / Model services

Copy .env.example to .env, set compatible planner/segmentation endpoints and the actual model identifier/revision, and restart. The bundled docs/model_services.md describes request/response contracts.

Check readiness in the connection panel before selecting Live mode. Live tasks send images to your configured endpoints. Fast/Tiled refinement are execution settings, not accuracy guarantees. Readiness does not establish prediction quality.

External weights, GPU dependencies and compatible model services are separate from this lightweight distribution. Failed live predictions never receive a procedural substitute.

09 / Troubleshooting

  • Pillow missing: install reviewer requirements with the interpreter used to start the software.
  • Port occupied: change --port and open the printed URL.
  • Comparison rejected: select distinct masked results of the same image, target and complement.
  • Empty mask: inspect it; empty output does not prove target absence.
  • Bundle verification failed: inspect the inconsistency without changing measurements to force a pass.
  • Services unavailable: check their configuration/readiness. Saved evidence still works offline.

10 / Supported scope and limitations

Single-image browser chips are limited to 12 MB and 16 million pixels. The headless core admits up to 64 million pixels, with bounded file/archive sizes and 100,000 connected components. Whole-image, one-half and rectangular pixel scopes are supported. Buildings/aircraft are primary use cases; roads, water, vegetation and ships are experimental.

This local single-researcher application has no geographic reprojection, multispectral processing, unrestricted agent execution, multi-user authentication or manual boundary editor. Measure model accuracy with independent reference labels and a frozen protocol.

Source is MIT licensed; external models and datasets have their own terms. This release candidate has no assigned software archival DOI.

Headless geographic extensions

The installed core also supports Polygon/MultiPolygon zones, exact replay packets, explicit raster bands/windows/scaling and optional detached Ed25519 signatures. These operations use the command line; the browser controls above retain pixel-based scopes.

python -m pip install ".[geo,signing]"
python examples/naip_zonal_workflow.py
geomasklab verify-zonal workflow-output/naip-zonal/zonal.zip
python examples/signature_workflow.py

The real NAIP example checks nominal square-metre areas against Rasterio/GDAL. Signature verification requires a separately trusted public key. Read docs/zonal_statistics.md, docs/raster_inputs.md and docs/signatures.md for input contracts, limits and trust assumptions.

Declared valid pixels

Prediction and validity masks have separate roles. A binary validity PNG includes white pixels and excludes black pixels on the displayed image grid. Describe its source and exclusion rationale; no cloud or NoData condition is inferred from image colors.

Use Region & validity to retain, replace or reset validity in a new result version. Whole-image and geometric-region ratios retain their original denominators. The valid-region card separately reports effective coverage, valid pixels and excluded pixels. Empty effective regions return undefined ratios, including after complementing a target.

Validity-aware evidence preserves analysis.json, valid_mask.png and original source_valid_mask.png bytes under format 2.0. Comparison, reference assessment and offline replay apply the same conditions. A comparison with no shared valid domain produces no difference image.

External masks and reference labels

Import a prediction PNG from another tool with the target, source and pixel-alignment confirmation. Use exact displayed image dimensions and binary 0/1 or 0/255 values. The software never resizes, thresholds or infers a class mapping. Source bytes are retained and the new result starts pending review.

Select a mask and click Evaluate reference. Reference foreground must denote the positive target, even when the selected result is a complement. Evaluation uses the saved spatial region intersected with declared valid pixels. It reports TP/FP/FN/TN, IoU, Dice, precision, recall, specificity and pixel accuracy. Empty denominators are undefined.

The error map uses mint for true positives, amber for false positives and magenta for false negatives. Export the evaluation packet to retain prediction evidence, supplied reference, scores, error image and hash manifest. Recompute with geomasklab evaluate prediction.zip reference.png --source "Reference description" --target building --aligned --output recomputed.zip.

Reference origin, alignment and independence are user assertions. Procedural examples test arithmetic only; a single image does not establish general model accuracy. Assessment does not alter the saved prediction or its review.

Replay a saved operation

Replay review packet accepts comparison, component, reference and batch ZIPs up to 12 MB in the browser. The same installed-core verifier reconstructs source pixels, conditions and calculations. The active experiment is preserved. Use CLI verification for larger packets.

geomasklab verify-comparison comparison.zip
geomasklab verify-components inspection.zip
geomasklab verify-assessment assessment.zip
geomasklab verify-batch batch.zip

Internal consistency checks do not authenticate origin or human review identity. Independently trusted signatures or external digests address a separate trust question.
