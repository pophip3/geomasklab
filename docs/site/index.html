Purpose

GeoMaskLab gives segmentation masks a reusable measurement and evidence workflow. Retain the exact image and source mask, select a pixel domain, show both coverage denominators, and let a colleague replay the result without the original model environment.

Bring any binary mask

Use aligned outputs from an annotation tool, GIS workflow, model or local baseline. Source assertions remain explicit.

Share a checkable result

Create portable evidence, recalculate its region and generate a standalone report after verification.

Install the reusable core

python -m pip install .
geomasklab verify evidence.zip
geomasklab recalc evidence.zip --scope right --output right.zip
geomasklab report right.zip --output report.html

The installed wheel needs only Pillow. The complete browser interface is bundled; run geomasklab-ui to start it. Model services and GPU model runtimes are external optional components. Core API, local providers and JSON Schemas describe the exact contracts.

A real-image denominator example

A credited NASA photograph of San Francisco Bay and a reproducible RGB color baseline are included in the source. Run python examples/real_image_handoff.py. The right-half mask covers 20.7199% of the whole photograph or 41.3173% of the selected half; the same foreground numerator uses two explicit denominators.

This is a pixel-workflow demonstration. The baseline is not human ground truth or validated tree/vegetation recognition. Image attribution and processing.

Getting started

Use Python 3.10 or newer. From an authorized checkout or source archive, run:

python -m pip install -r requirements.txt
python reviewer_demo.py
python quickstart.py

Open http://127.0.0.1:4180 in a browser. The Python process serves the interface locally. If that port is occupied, run python quickstart.py --port 4182 and open the printed address.

The offline demonstration requires only Pillow. It needs no GPU, account, model weights or inference endpoint. Built-in images and masks are procedural fixtures, clearly labeled as synthetic; they are not satellite observations or neural predictions.

New application labels, messages and generated evidence reports are in English. User-entered content and imported historical records retain their original text.

Analysis workflow

  1. Choose an image. Use a labeled fixture for software checks, or upload a supported RGB image for model-assisted analysis.
  2. Select the task. Request one semantic category and one spatial scope. An English fixture request is Segment buildings in the right half.
  3. Inspect the output. Compare the original, overlay and binary mask. Candidate connected components are not validated object counts.
  4. Record a review. Accept, reject or leave the result pending, with a reviewer identifier and explanation. Review is self-reported and bound to the saved image/mask hashes.
  5. Export the evidence. Retain the ZIP alongside its source version and configuration. A completed computation still requires semantic inspection.

Two coverage values, two denominators

The same foreground mask can answer two different questions. Let A be its positive pixels, I the total image pixels and R the selected-region pixels.

Whole-image coverage: A / I — how much of the entire image is covered?

Within-region coverage: A / R — how much of the selected region is covered?

In the procedural rectangle example, 12,850 foreground pixels occupy a 40,000-pixel region in a 480,000-pixel image. Whole-image coverage is 2.6771%; within-region coverage is 32.125%. Neither percentage is an accuracy score or a geographic area measurement.

Coordinates are zero-based with exclusive upper bounds. Odd dimensions split at the integer midpoint. An empty half-image has undefined within-region coverage, recorded as null. Older records without the new fields remain readable.

Review and recalculate saved evidence

Import an evidence ZIP to create a new local session. The verifier checks file identities, aligned binary masks, spatial replay, recorded statistics and review bindings before the result is restored.

Select a mask and click Region & validity. Choose the whole image, a pixel half or the current rectangle ROI. Draw a new rectangle before opening the dialog if needed. This creates a separate result version with pending review; it preserves the semantic target, complement setting and original full-mask bytes.

The operation calls neither the agent nor the segmentation service. It changes the measurement region; it cannot improve an inaccurate mask or recover a missing target. Original prediction timing is retained as historical metadata, separate from local recalculation time.

python -m workbench.export_bundle path/to/evidence.zip
python examples/recalculate_region.py reviewer-output/right.zip

Single-result import does not restore the complete ancestor history. Hash checks establish consistency, not source authentication or semantic correctness.

Declare which pixels are included

Import or replace an aligned binary validity PNG: white includes pixels and black excludes them. Record the source and exclusion rationale. All pixels are declared valid when no exclusions are supplied; image colors do not automatically define clouds or NoData.

Region & validity retains, replaces or explicitly resets validity in a separate pending-review version. Geometric and valid denominators are displayed separately. Empty valid domains have undefined ratios. Evidence format 2.0 preserves the original validity upload, normalized mask, realized configuration and replayed counts; legacy format 1.0 remains readable.

python examples/validity_workflow.py --geo
geomasklab verify valid-evidence.zip --schema

Validity inputs, denominators and replay contract

Use external masks and reference labels

Upload an image and select Import mask. Provide an aligned binary mask, its target and its source. This creates a new pending-review version without model inference. Exact dimensions and 0/1 or 0/255 pixels are required; no resizing, thresholding or class mapping is inferred.

Select Evaluate reference to compare a saved result against supplied positive-target labels. The saved spatial region intersected with its declared valid pixels defines the evaluation domain. Examine IoU, Dice, precision, recall, specificity, pixel accuracy and a true-positive / false-positive / false-negative error map. Undefined ratios remain null.

The assessment ZIP retains prediction evidence, reference labels, metrics, error image and a hash manifest. Reference quality, independence and alignment remain user assertions, and procedural examples establish software behavior only.

python examples/reference_workflow.py

Optional standards and geographic assessment

Export a source-bound PROV-JSON mapping without extra core dependencies. A separate GeoTIFF assessment reads declared CRS units, checks exact RGB pixel alignment, measures nominal projected or WGS84 geodesic-corner area, and exports a mask on the original coordinate grid.

The geographic extra uses Rasterio and pyproj. Nodata domains, unsupported geodesic CRSs and missing transforms are rejected. Core evidence retains pixel measurements; physical assumptions stay explicit in a separately replayable packet. Inputs, units and limitations.

Configure external model services

Live segmentation requires your own compatible RemoteAgent and RemoteSAM endpoints. GeoMaskLab does not bundle their model implementations or weights. Copy .env.example to .env and configure the verified endpoints and model identifier:

GEO_AGENT_BASE_URL=http://127.0.0.1:8000/v1
GEO_AGENT_MODEL=RemoteAgent
GEO_AGENT_API_KEY=
GEO_REMOTESAM_URL=http://127.0.0.1:6657/predict
GEO_REMOTESAM_REVISION=your-verified-model-revision
GEO_SERVICE_PROXY_MODE=direct

These are examples, not public inference services. Configure a credential only if your service requires one. Uploaded images are sent to the configured services in live mode; keep private credentials out of the repository. A finer processing mode does not guarantee higher semantic accuracy.

Offline evidence review and saved-mask recalculation remain available without those services. Full independent model-service installation acceptance is still pending.

Investigate versions and manage experiments

Compare verified masks

Inspect shared and changed foreground within the intersection of both selected regions and both declared valid masks. Choose an explicit shared-domain or identical-domain policy. Separate prediction, geometry and validity changes; explain foreground accounting; export both exact sources and categorical differences in a replayable comparison packet. Agreement is not ground-truth accuracy.

Keep an experiment library

Save names, notes and pins, search investigations and filter those awaiting review. Export all recorded requests as CSV with both coverage denominators, missing measurements and failed requests retained.

The English workflow guide includes a pausable schematic animation and respects reduced-motion settings. A complete offline manual ships at workbench/web/help.html and is served at /help.html; local fonts and assets keep it available without an internet connection.

After dependency installation, use bin\geomasklab.cmd on Windows or sh bin/geomasklab.sh on Linux/macOS. Both prefer the root virtual environment and accept a custom port.

One connected, offline workflow

Declare valid pixels and a region, compare masks under explicit conditions, inspect candidate boundaries, execute paired batches reliably, then let another environment replay the exported operation. The source includes a real NAIP workflow with independent pixel-set arithmetic and deliberate failure/empty-domain cases.

python examples/five_step_workflow.py
geomasklab verify-comparison five-step-output/comparison.zip
geomasklab verify-components five-step-output/components.zip
geomasklab verify-batch five-step-output/batch.zip

Boundary-aware review

Stable 8-connected IDs, exclusive bounding boxes and image/region/invalid edge flags help locate potentially clipped candidates. Filters leave source evidence unchanged.

Reliable explicit batches

Manifest pairings, isolated failures, cooperative cancellation, crash-safe locks and verified resume retain completed work. Macro and micro coverage use declared valid denominators.
