# GeoScope 软件定位与逐项验收

日期：2026-10-05。开发版本：0.9.0-dev.2。当前优先完成软件；论文文字暂缓。
改动仅在独立研究仓库。现有场景理解、目标提取、范围修改、统计、版本选择和导出主流程保留。
用户已说明“一两分钟”不是硬性要求；运行时间只作记录，不设固定验收时限。

## 1. 要解决的具体痛点

候选痛点：研究者用自然语言连续修改影像分割任务后，其他人需要知道最后结果来自哪幅
输入、哪个目标和实际模型请求、哪次父结果、哪个像素范围及面积分母，并能在没有原模型
服务的电脑上复算这些数值、检查结果是否经过人工复核。

这里的科研任务是“可核查的交互式遥感分割实验”。建筑和飞机作为两个具体应用入口；
目标提取、像素覆盖分析和标注前检查仍是主功能。每次请求产生可区分的结果版本，
结果包保留复算所需的输入和完整掩膜，复核决定绑定到该版本的精确文件。

这是可测试的软件问题陈述，尚未证明是整个领域首次解决的空白。已有处理历史、
分割导出和人工标注能力必须如实承认，不能将单项通用功能作为本软件首创。

以下为官方文档核查。2026-10-05 已实测 Label Studio SDK 的 brush 转换器；其余工具仍未做完整实装比较。详见 [实际价值验证](workflow_value_zh.md)。

| 工具 | 文档明确提供的能力 | 对本项目定位的约束 |
|---|---|---|
| [SAMGeo](https://samgeo.gishub.org/) | 文本提示分割、保存提示、常见矢量导出、交互地图；已有 JOSS 软件论文 | 不能宣称首次文本提示遥感分割或首次导出分割结果 |
| [QGIS Processing](https://docs.qgis.org/3.44/en/docs/user_manual/processing/history.html) | 参数及执行历史、复制命令/JSON、重运行 | 不能宣称首次记录或复现处理历史 |
| [Label Studio](https://labelstud.io/guide/export.html) | 预测和人工标注的关联、审核后标注导出、多种格式 | 不能宣称首次人工复核或首次标注导出 |

| [MICCAI 2026 图像处理代理框架](https://papers.miccai.org/miccai-2026/0049-Paper2038.html) | 摘要描述产物契约、代理规划、确定性执行和溯源；应用在医学影像 | 不能把代理与确定性执行分离、产物溯源作为跨领域全新架构 |

候选差异是组合工作流：受限自然语言规划 → 固定输入和父版本 → 确定性像素范围
操作 → 自报语义复核 → 自包含结果包 → 无模型服务的离线数值复算。
仅靠上述文档没有建立“其他工具不存在此组合”的结论；下一阶段需要按同一任务
实装对照，记录完成步骤、依赖、手工拼接、出错恢复和交付文件，允许发现已有等价方案。

需要扩展阅读和比较相近的代理式遥感、交互分割与实验溯源软件后，才决定最终新颖性表述。
若差异有限，就收窄应用目标或改进具体缺口，不通过扩大影响描述替代证据。
阅读到的 [遥感代理技术挑战立场论文](https://arxiv.org/abs/2604.24919)
指出工作流状态变化和跨步骤错误传播问题，支持本项目关注运行正确性的动机；它不证明
本项目具体方案的新颖性。上述论文仅完成摘要层阅读，不能写成已全文精读。
本轮精确检索“GeoScope SoftwareX”没有检出对应条目，这不是首次发表的充分证明。

## 3. 软件边界与可增加的小功能

- 首要应用：建筑、飞机。已有独立应用结果反映了明显质量限制，首要应用不等于可靠识别。
- 道路、水体、植被、船舶保留为实验类别，界面、服务状态与报告明确标识。
- 输入为一幅 RGB 图；全图、单个像素半幅、矩形 ROI。当前没有地理参考或平方米统计。
- 连通区域是待核查的候选区域，不作为准确实例计数。
- 增补只围绕复核记录、可靠报告、审稿快速入口、模块化接口和失败恢复。
- 暂不扩展成多用户平台、通用 GIS、模型训练平台或无限制自主代理。

## 5. 本轮实质改动

`product_contract.py` 集中定义软件版本、类别定位和度量边界。
`semantic_review.py` 定义独立的复核记录契约与文件身份验证；`server.py` 提供保存接口，
界面允许接受、拒绝、退回待复核。复核不会改掩膜、统计或模型，也不继承到新结果。
导出器同时保留执行软件版本和导出生成器版本，旧记录没有版本就注明未记录。

报告根据实际 `service_request` 记录语义类别或指代表达，不再把固定默认提示当作实际
请求。界面将服务的 `accurate` 模式称作“分块细化”，不承诺其精度更高。
`reviewer_demo.py` 与 `quickstart.py` 提供无 GPU 的运行入口，流程使用明确标注的程序生成数据。
这些改动针对可维护性、审稿复现和结果解释；没有改变核心分割算法。
新开发版也在一幅此前用过的开发影像上完成真实 RemoteAgent/RemoteSAM 调用；实际请求
为建筑语义分割，服务检查点进入报告，导出离线验证通过。这是软件连通与记录验收，
不是新增独立精度实验；本机记录保存在 `runtime/acceptance-v09`，原始影像不提交到仓库。

## 6. 科学意义与应用价值如何建立证据

开发动机应围绕让交互式分割结果进入可检查的研究过程：他人能够发现错误分母、
错误范围或版本混用，而不依赖作者截图和无法访问的模型服务。其价值在于提高实验
交付的可检查性和降低复算门槛；是否减少实际研究时间或错误，要由同任务对照测量。

实例应覆盖成功、空目标、漏检/误检、连续修改与拒绝结果；展示哪些问题由程序发现、
哪些需要人识别。不能只选择最好看的影像，也不把合成例当作真实模型能力证据。

潜在用途包括遥感方法探索中的目标覆盖检查、模型输出与标注前检查、教学演示、
科研结果附件审核。它们目前是待验证用途，没有工业采用或用户研究数据。
建筑覆盖是像素比例，不能直接推断城市发展、灾损面积或地面规划结果。

后续影响表述必须与已实现能力、真实案例及对照测量相连。没有用户调查、工业部署或
效率实验时，不写已改善行业决策、已广泛使用或已提高推理速度。
