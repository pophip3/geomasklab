## 改造的判断标准

保留经过验证的比赛功能，以真实科研用途、独立复现和可核查结果为依据改造。
不以更名、换色或改写论文文字作为主要贡献，也不隐瞒比赛来源。
新版本是否具有发表价值取决于实际能力及支持它的证据，不能根据修改行数或功能数量判断。

| 模块 | 比赛版本的基础 | 研究版的实质改动 | 目前可提供的证据 |
|---|---|---|---|
| 规划器接口 | 调用外部规划模型提出工具请求 | 独立实现受限协议解析器，固定当前输入身份，反馈回合不再执行工具 | 非法表达式、调用链、路径绑定和回合权限回归 |
| 结果包 | 保存最终结果供下载 | 加入完整正类掩膜、逐文件 SHA-256 清单和离线复核入口 | 导出可重建裁切、反选和覆盖率；错误分母即使重算哈希也被发现 |
| 范围处理 | 支持半图、ROI 和父版本继承 | 修复合成模式下 ROI 与继承半图发生隐式相交的问题，按统一规则拒绝冲突 | 回归覆盖拒绝冲突及显式恢复全图后的正确 ROI 面积 |
| 示例资产 | 使用比赛演示影像 | 程序生成图形及其确定性掩膜，明确不是真实遥感观测或模型预测 | 示例从源码可重建；全图、左右半图及 ROI 导出都能独立复核 |

| 实验报告 | 保存运行信息 | 实际模型请求、语义类别、嵌套服务版本与检查点记录 | 回归验证语义分割不会被误写为默认文本提示；演示不虚构模型请求 |

## 当前完成和尚未完成的工作

已形成研究版代码、合成示例、离线复核器和 76 项通过的回归测试。
本地运行通过的合成矩阵为 60 组；这些是软件处理与导出一致性证据，不是遥感分割精度。
历史模型统计已复算，但同一测试集的调参结果不当作独立泛化证据。

旧提交的独立60图真实服务评估已完成，结果保留不改写。尚未完成：候选差异的实装对照、
新开发版完整交付验收、必要的质量优化及新冻结评测、最终正式许可证、作者及声明核实，
以及公开固定版本。研究版已作实质修改，并不因此自动满足 SoftwareX 接收标准。

## 下一步开发与验证顺序

1. 按 [软件定位与逐项验收](software_definition_zh.md) 确定痛点，保持主功能，优先审稿入口和可靠复核。
2. 完成同任务已有工具对照，检查可复现性与实际使用收益。
3. 若需改模型策略，在开发图上完成优化，再用新冻结数据验证；旧结果保留。
4. 完成清洁安装、真实案例交付、许可和固定版本，确认软件验收。
5. 软件稳定后再完成论文文字及投稿材料。

## 出版时应如何说明来源

论文和 README 写清研究软件由比赛工作台发展而来，提供原提交哈希和研究版变更记录。
分别引用外部模型、相关软件和数据来源。我们报告工作台的任务约束、结果可追溯性与数值复核，
不把外部模型的算法、训练和指标归为本软件新贡献。
