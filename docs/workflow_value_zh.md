# GeoScope 与已有工具的实际价值验证

日期：2026-10-05。版本：0.9.0-dev.2。主分割流程及模型保持原有行为。

## 目前可成立的定位

将自然语言驱动的遥感分割结果交给另一个研究者时，需要交付足够信息，使对方在
没有原模型服务的条件下检查：影像是否对应、范围是否一致、统计分母是否正确、
候选计数是否来自这份蒙版、已有复核记录是否绑定到同一结果。

本轮实现并验证的是结果交接与领域一致性检查。它有明确用途：审稿附件核查、
同组研究者复查模型输出、分割结果进入人工标注前的检查。尚未建立“领域首次”、
用户工作时间减少、模型精度提升或工业采用证据；当前不以这些作为软件贡献。

## 已有能力与比较边界

| 参照工具 | 已有能力 | 本轮证据级别 |
|---|---|---|
| [Label Studio 官方 SDK](https://github.com/HumanSignal/label-studio-sdk/tree/master/src/label_studio_sdk/converter) | brush PNG 与 RLE 转换；预测与人工标注格式 | 实际运行 PyPI 2.1.2 包中的官方 brush 转换器；没有启动完整 Web 服务 |
| [Label Studio 标注导出](https://labelstud.io/guide/export.html) | 多种标注及预测导出格式 | 官方文档核查；不能声称它缺少人工复核、导入导出能力 |
| [QGIS Processing](https://docs.qgis.org/3.44/en/docs/user_manual/processing/history.html) | 参数与处理历史、命令及 JSON 复制、重运行 | 官方文档核查；本机没有 QGIS，未实装比较 |
| [SAMGeo](https://samgeo.gishub.org/usage/) | 交互分割、栅格/矢量输出等遥感能力 | 官方文档核查；本轮未实装，不能声称精度或效率领先 |
| [SemanticSeg4EO](https://github.com/aleguillou1/SemanticSeg4EO) | 地理影像训练、交叉验证、滑窗推理、地理配准及置信度输出 | 官方源码仓库说明核查；不同任务和模型，未做数值对比 |

QGIS、SAMGeo 等已具有更完整的 GIS 能力。GeoScope 当前统计为像素量，不提供
地理面积；不能用界面功能表暗示全面替代这些软件。组合工作流的差异仍需更多
实装与用户任务研究；文档没列出的功能不等于工具没有该功能。

## 同输入、同掩膜的受控实验

脚本：`examples/compare_handoff.py`。使用程序生成的两个影像及确定性掩膜，覆盖
全图建筑、右半幅、左侧分支、矩形 ROI、飞机五个结果。所有方法使用同一份保存
的掩膜；不重跑神经模型，从而避免把模型差异混入交接流程比较。

现有工具路径真实调用官方 `image2rle` 和 `decode_rle`，检查 PNG → RLE → 像素
往返；GeoScope 的适配器也使用同一官方编码器。GeoScope 交接路径进一步执行
实验包校验 → 新会话恢复 → 模拟重启重载 → 再导出，并比较文件字节。
`post_json` 被替换为一旦调用就报错的函数，保证导入过程没有调用模型。

本机软件环境：Windows 11、Python 3.13.9、Pillow 12.0.0、NumPy 2.3.5。
实际第三方包为 `label-studio-sdk==2.1.2`；其 `brush.py` SHA-256：
`8d12f77cb97f274e9f5445fb51ab77d6bbb4b9467bd42e33ad79d7daa39cac8a`。
包取自 [官方 PyPI 发布](https://pypi.org/project/label-studio-sdk/2.1.2/)，单独加载转换器，
没有冒充完整标注服务器测试。

| 结果 | 前景像素 | 官方转换器像素往返 | GeoScope 适配器往返 | 导入后原图/完整掩膜/最终掩膜/统计 |
|---|---:|---|---|---|
| 全图建筑 | 75,350 | 完全一致 | 完全一致 | 文件字节完全一致 |
| 右半幅建筑 | 37,350 | 完全一致 | 完全一致 | 文件字节完全一致 |
| 左侧分支 | 38,000 | 完全一致 | 完全一致 | 文件字节完全一致 |
| ROI 建筑 | 12,850 | 完全一致 | 完全一致 | 文件字节完全一致 |
| 飞机 | 22,532 | 完全一致 | 完全一致 | 文件字节完全一致 |

各方法在正常输入上都通过。GeoScope 的增量价值不是更精确的 RLE 编码，而是同包
检查任务和结果的关系，并可在无模型条件下恢复和继续记录复核。
复核状态保持原值；右侧样例的 accepted 是显式注明的自动化持久化检查，不是人工
给模型打分。所有样例都不能用来计算真实遥感模型的语义精度。

## 四个错误注入案例

在右侧样例上分别改动一个字段，并重新生成所有文件校验和，排除“只靠哈希发现
文件变动”的解释。官方 brush 转换器仍能正确转换未改变的蒙版；GeoScope 在
创建新实验前拒绝不一致的包。

| 错误 | GeoScope 检查 | 结果 |
|---|---|---|
| 覆盖率误用半幅分母 | 从实际蒙版及整图尺寸重算覆盖率 | 拒绝 |
| 任务 ROI 与统计 ROI 不同 | 对齐任务、报告选项和统计的 ROI | 拒绝 |
| 复核记录绑定了另一份蒙版 | 检查运行编号、影像及蒙版 SHA-256 | 拒绝 |
| 候选数量被改动 | 从最终蒙版重算八连通候选及其统计 | 拒绝 |

这些元数据检查不属于 brush 格式转换器的职责。不能将其未做这些检查写成
Label Studio 的缺陷，也不能把上述四个预设案例称作实际研究错误的发生率。
对照展示的是需要另外编写的领域校验已经由 GeoScope 集成；没有证明其他工具
无法通过脚本扩展实现同样检查。

## 真实输出交接检查

另取此前 0.9.0-dev.1 已运行过的一份建筑模型结果包，输入为 800 × 600 的开发
影像，前景 134,003 像素。新版本导入、重载、再导出均通过，四类像素产物文件
字节一致，实际模型请求和服务元数据保留，模型调用数为零。记录见
`evaluation/workflow/live_handoff.json`。这只是已有真实输出的交接验收，没有新增
独立影像，没有重测精度；原始影像和实验包不进入研究仓库。

## 软件增加的内容

- 网页“导入实验包”：先验证，再新建本地会话；保留来源 ZIP 与来源版本。
- 导入图像不重新编码，避免改变影像身份；URL 换成本机地址，来源缓存提示不继承。
- 独立 `pixel_geometry.py` 复用候选计算，使命令行验证和网页使用同一规则。
- 可选 `label_studio_export.py` 输出 brush predictions 和配置；不生成人工 annotations，
  不把接受记录变成 ground truth，不编造模型置信度。
- 修复历史页复核状态显示；记录复核时需要明确选择决定。

单结果包不含完整祖先分支；导入页明确显示来源版本。继续记录复核不需模型；
新增分割需用户选择模型模式。哈希与数值一致不能验证提交者身份或目标语义正确。

## 复现与后续证据

```sh
python -m pip install -r requirements.txt
python -m pip install -r evaluation/requirements-evaluation.txt
python -m pip install --no-deps label-studio-sdk==2.1.2
python examples/compare_handoff.py
```

最后一项输出 `workflow-output/summary.json`。仓库保存本轮数值记录于
`evaluation/workflow/summary.json`；生成的合成图片与任务 JSON 保留在本机输出目录。
基础工作台及轻量演示依然只要求 Pillow。

当前 81 项软件测试、60 组像素矩阵及原有四例导出均在本机通过；跨平台 CI 对
本次提交还需查看实际结果。实验记录的耗时执行了不同数量的工作，不用于性能排名。

下一步应在同一真实科研任务上实装 QGIS/SAMGeo/完整标注工具工作流，并让独立
使用者执行“恢复他人结果、检查分母与范围、形成可复查附件”的任务，测量成功率、
需要手工拼接的内容、恢复失败的原因与操作时间。允许找到已有等价方案，并据此
收缩定位；没有实际数据之前不填写节省百分比或“唯一工具”的结论。
